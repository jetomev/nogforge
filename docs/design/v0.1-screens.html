nogForge · design proposal · 3 October 2026

nogForge, screen by screen

nog's wrapper, with what Pamac does, in a terminal. Every screen drawn before any code is written, at exactly 100 columns. The numbers are this desktop's, read on 3 October; anything made up for the picture says "example".

Your brief: "I want to do the wrapper, but also have the functionalities of Pamac GUI on a TUI." The look is grubForge 2.0's, like alacrittyForge and bitlaForge: boxes on the Dashboard, forms in Settings, a review before anything changes, the hint line at the bottom.

Decided · Javier, 3 October

  1. Screens: Dashboard ("sexy"), Home, Search, Update ("looking forward to it"), Tiers ("Amazing!"), Settings, History, Help, Quit.
  2. System packages can't be removed unless nothing needs them: Tier 1, Arch's base set, and anything another package needs show a lock and the reason.
  3. The password works like grubForge's: the system's own window; nogForge never sees it.
  4. Repositories can be added and removed, with signatures required and the key checked before it's trusted.
  5. nog 1.6.0 comes first: "Yes".
  6. Beta (0.x) until everything is there, Flatpak and Snap included: "no full release until we have everything figured out".
  7. Version 2 of this page (Javier's notes): every list a spreadsheet-style table with shaded alternate rows; package rows are Icon · Name · Version · Tier (written out) · Option on the right, with the description underneath and no heading; options at the right of their row, like Promote; screen buttons at the top only, never repeated at the bottom; buttons read "Review Updates (u)", the format for every Forge Suite app from now on (what's already shipped changes in its next version).

nog does the thinking; nogForge shows it

Tiers, hold dates and which packages must move together are nog's. nogForge never works them out itself: two copies of that logic would sooner or later disagree. So nog 1.6.0 learns three things first:

1 · Speak in data

A --json option: the update plan, tiers, holds and search, as data nogForge can draw tables from instead of reading text off a screen.

2 · Keep these back

Given the updates you unticked, nog answers what else must stay back with them ("mesa needs lib32-mesa and vulkan-radeon to match"). No broken combination can be built.

3 · The password window

When nogForge calls it, nog asks for the password through the system's window instead of the terminal.

The password

Like grubForge: when a change needs administrator rights, the system's own password window opens (on KognogOS, KDE's). nogForge only learns "allowed" or "cancelled". nog runs as you, because building AUR packages refuses to run as administrator; only its administrator steps ask. On a text console, with no window, the terminal asks instead.

Beta phases

  1. nog 1.6.0: JSON, keep-back, the password window. Released and tested by you first.
  2. nogForge 0.1: Dashboard, Home, Search, install and remove, History.
  3. 0.2: Update, the visual plan.
  4. 0.3: Tiers.
  5. 0.4: Settings, repositories included.
  6. Later: Flatpak and Snap installs (nog#7), then 1.0.

Each phase: tests, every distribution nog runs on, your run with a written test matrix, then the beta release.
